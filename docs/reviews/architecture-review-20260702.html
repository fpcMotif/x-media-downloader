Architecture review — nix-config

2026-07-02 · target darwinConfigurations.f · explored by haiku/sonnet sweeps, verified by fable

module seam leakage deep module
Verdict: this config follows best practice unusually well — thin flake, one deep constructor, real eval-time tests, ADR discipline. The weaknesses are concentrated: discipline drift inside modules/home/claude.nix, knowledge duplicated at the CI seam, and one IFD that leaks build-time work into every eval.

What is genuinely good — 5 aspects, each with a lesson

1 · Documentation as a maintained contract

ARCHITECTURE.md (556 lines) carries a "Last reviewed" date, update-in-same-PR rules, a layer table with one writer per concern, and states positions even when the answer is "none today" (secrets row). PANIC.md is a real rollback runbook.

Lesson: a doc that states positions ("secrets: none, revisit before X") is testable by reading; a doc that describes files is stale on arrival.

2 · ADRs that record negative decisions, plus a pinned vocabulary

9 ADRs, several of the form "re-adding X is a regression, not a gap" (gemini removal, Dropbox exception). CONTEXT.md defines terms, flags its own ambiguities, and includes example dialogues; docs/agents/ wires agents to read them first.

Lesson: write down what you decided not to do — those are exactly the changes agents and future-you keep re-proposing.

3 · Thin flake, one deep constructor, single-writer facts

flake.nix is a host table + output wiring. lib/mkSystem.nix computes currentSystemUser/currentSystemUserHome once and threads them via specialArgs — zero /Users/martinfan literals anywhere in modules/. The one invariant Nix can't enforce (flake attr ≡ hostname) is pinned by an eval test instead of a comment (mksystem-test.nix).

Lesson: compute a fact once and thread it; when the language can't enforce an invariant, pin it with a cheap eval assertion.

4 · The update stack is a textbook deep module

scripts/lib/auto-update.sh (262 lines) hides version polling, SRI prefetching, safe in-place edits, and the assert-clean guard behind a dozen au_* functions; 17 updaters are thin adapters (14–73 lines). Past incidents are encoded as library rules: never sed -i, never commit FAKE hashes, every updater idempotent. Even the cron cadence change documents its economics in the workflow comment.

Lesson: turn postmortems into library invariants, not memory — the fix lives where the next caller can't avoid it. Leverage: one implementation, 17 call sites.

5 · Evaluation as a free test harness

Unit checks (mksystem, overlay, format, skill-router) + integration checks (572-line configurations-eval, darwin-settings, linux-purity) run through nix flake check on both CI arches. Inactive hosts (wsl, x230, vm) stay in the eval matrix so they can't bit-rot silently. The expensive tier (macOS activation VM) is consciously designed-and-deferred in ADR-0004 + a design doc.

Lesson: in Nix, assert on the evaluated config, not the live system — and write down the test tiers you're deliberately not building, with why.

20 points that fall short — why, and the aspect to improve

Ordered roughly by severity. Chips name the aspect needing improvement.

  1. 1 · modules/home/claude.nix is a 568-line shallow-interfaced monster. modularity
    It mixes ≥6 concerns (dotfile installs, debug hooks, skill curation policy, session-file surgery, plugin surgery, settings seed, skills DSL) and is the sole consumer of 5 of 11 flake inputs. A maintainer's interface — everything they must know to touch it safely — spans chezmoi templating, jq, the plugin-cache layout, and the agent-skills DSL. Two ~50-line markdown footers are inlined as Nix strings (content-as-code; they belong in sibling .md files). Deletion test: deleting it scatters, not removes, complexity — but so does keeping it whole. → Candidate A.
  2. 2 · Five activation blocks violate the repo's own DRY_RUN guardrail. correctness
    ARCHITECTURE.md's guardrails require activation blocks to "respect DRY_RUN without mutating the filesystem". claudeStopHookDebug:368, surgeAgentSkillSymlinks:412, claudeDisableGrillSkills:430, claudeDisableRefactorPluginCodeSimplifier:460, claudeDisableGlobalMcpPlugins:508 all mutate unconditionally; only claudePruneRemovedSkills:401 complies. A dry activation actually rewrites ~/.claude and plugin caches.
  3. 3 · The agent-skills IFD leaks build-time work into every eval. purity / CI
    tests/default.nix:49-51 and auto-update.yml:82-84 both document the fallout: nix flake check --no-build is impossible, the nightly guard hand-picks two check attrs, darwin can't eval the Linux hosts, and the linux-purity check must skip on darwin. Two prior fixes failed. The jj skill already ships the alternative adapter — a plain path symlink (claude.nix:336-342). → Candidate C.
  4. 4 · "Which checks does CI run?" is answered in three places. locality
    tests/default.nix defines them; build.yml hardcodes 10 attr names twice (Linux + darwin jobs); justfile check runs a 3-attr subset. Adding a test means three edits or silent divergence — no leverage. → Candidate B.
  5. 5 · Version-pinned paths into a mutable plugin cache. fragility
    claude.nix:393-394 targets ralph-loop/1.0.0 and codex/1.0.4 literally; a plugin update silently no-ops the debug wrapping. The sibling block at :461 already shows the right shape — glob the version directory.
  6. 6 · Temporary diagnostics live in the permanent baseline. lifecycle
    stopHookDebug (43-line script + activation block) says "restore … when diagnosis is done and this block is removed" — but nothing expires it. Debug instrumentation without an off-switch becomes baseline. Gate it behind an enable option or delete it.
  7. 7 · 19 of 23 home modules have no enable seam. options discipline
    claude.nix, zsh.nix, lsp.nix are unconditional fragments — a host can't opt out without editing the module. The staged Omakub/Linux profile will want most-but-not-all of the set. Contrast: 10/18 darwin modules and ghostty/prompt do this right. → Candidate D (scoped, not blanket).
  8. 8 · No checks run on aarch64-linux at all. coverage
    checkSystems (flake.nix:70-73) excludes it, so the vm-aarch64-utm host gets a toplevel build but zero unit/integration checks — even though CI already has a native ARM runner sitting there.
  9. 9 · Substituter asymmetry between workflows. CI cost
    auto-update.yml:45-49 configures claude-code.cachix.org; build.yml's four jobs configure no substituter — PR CI rebuilds what the nightly gets from cache. Share one Nix-install step.
  10. 10 · Six inputs track moving branches. supply chain
    mattpocock-skills, effect-ts-skills, superpowers, agent-skills, nixos-wsl pin main/master. The skill sources are also a prompt surface for every agent session — a branch push upstream lands in your context on the next flake update. Pin tags/revs where upstream has them; the nightly bump can still roll them deliberately.
  11. 11 · Two ADRs share number 0008. process
    0008-code-dev-first-skill-catalog.md and 0008-reproducible-dev-envs…md. "See ADR-0008" is now ambiguous — the whole point of numbering. Renumber the newer one to 0009.
  12. 12 · A stale plan doc describes work that already shipped. docs drift
    docs/karpathy-observable-signals-plan.md proposes "Observable signals" footers "blocked on merge conflict" — but the footers are live in claude.nix:68-74, 94-99. Delete or archive it.
  13. 13 · The repo root reads like a scratch desk. hygiene
    result-1 (stale test-build symlink), autoresearch.jsonl + autoresearch.config.json + progress.md (external-harness telemetry), untracked droid-wiki/, one-off AGENT_SKILLS_NIX_REPORT.md. Gitignore result*, move telemetry out, park reports under docs/reports/.
  14. 14 · codex sits outside the martin.* namespace. policy drift
    pkgs/default.nix:8 exposes a vendored derivation at overlay top level, contradicting ARCHITECTURE.md's "pkgs.martin.* is the canonical place". Move it under martin (keep a top-level alias during migration if modules reference pkgs.codex).
  15. 15 · An unexplained global override. undocumented exception
    pkgs/default.nix:4-6 disables direnv's test suite for every consumer with no comment. Every deliberate exception in this repo carries a rationale (ADR-0005, google-drive's URL note) — this one doesn't. Add the why, or drop it if upstream fixed.
  16. 16 · The filename glob forces no-op adapters. convention smell
    update-claude-code.sh/update-crush.sh are 14-line stubs, and update-flake-inputs.sh exists (its own header says so) only because the sweep is for s in scripts/update-*.sh. The convention is the interface, and it's forcing empty implementations. A manifest of real updaters would drop the stubs.
  17. 17 · The update sweep has two writers. duplication
    auto-update.yml:57-68 and justfile bump-and-switch implement the same loop independently. Let CI call just bump so the sweep has one implementation, two callers — leverage instead of copy.
  18. 18 · legacyPackages is an ad-hoc export surface. interface consistency
    It exposes exactly { crush, martin } — a NUR passthrough sitting beside the owned namespace, and no darwin packages output at all. Decide the export policy once: what does nix build ~/nix-config#… promise?
  19. 19 · zsh.nix: 548 unsegmented, optionless lines. navigability
    Second-largest module, no internal section markers, no options. It will be the first module the Linux profile needs to partially reuse. Segment it (env / aliases / integrations / wrappers), and give the darwin-only wrappers an explicit sub-seam.
  20. 20 · Some tests pin implementation strings, not interfaces. test brittleness
    darwin-settings-test.nix:249-269 locks exact skhd keybind strings; mksystem-test.nix hardcodes "martinfan"/"f". Drift-lock tests are legitimate — but where module and test can read one shared constant, derive both so a deliberate tweak is a one-place edit, and the test still catches accidents.

Deepening candidates

A · Deepen "managed app-state surgery" into one home-side module

Strong in-process

modules/home/claude.nix · cursor.nix · lsp.nix · opencode.nix — exemplar: modules/darwin/baseline-activation.nix

Before — the same bash blob, 12+ times

claude.nix

jq + .origjq + .origseed-oncesweepsweeppark+stripsymlink

cursor.nix

settings copyextensions

lsp.nix

json-mergejson-merge

opencode.nix

seed-once

each blob re-decides: backup? idempotence? DRY_RUN? — 5 of 7 in claude.nix get DRY_RUN wrong

After — one deep module, thin callers

martin.home.appState

declare { file; action = seed | jq-edit | sweep | park; backup; }

implementation owns: .orig ledger · mktemp/mv · idempotence check · DRY_RUN contract · logging

claude.nix
declares 7 cursor.nix
declares 2 lsp.nix
declares 2 opencode.nix
declares 1

the design already exists in-repo: baseline-activation.nix did exactly this for launchd state

Problem: the "reversible surgery on mutable app state" pattern is re-implemented ad hoc ≥12 times; correctness rules (DRY_RUN, backups, idempotence) are re-decided per blob and drift.

Solution: lift baseline-activation.nix's typed-declaration design to the home layer; callers declare state edits, the implementation owns the contract.

  • locality: DRY_RUN fixed once, fixed everywhere
  • leverage: one implementation, 12+ declarations
  • claude.nix shrinks ~160 lines
  • eval tests can assert the contract per declaration

B · One interface for "what CI runs"

Strong local-substitutable

tests/default.nix · .github/workflows/build.yml · justfile

Before — three writers

flowchart TB
  T["tests/default.nix
defines 10 checks"]
  W["build.yml
hardcodes 10 names ×2 jobs"]
  J["justfile check
hardcodes 3 names"]
  T -.drift.-> W
  T -.drift.-> J
  classDef leak stroke:#dc2626,stroke-width:2px;
  class W,J leak

After — one source, two adapters

flowchart TB
  T["tests/default.nix
groups: ci-gate · smoke"]
  E["nix eval .#checks --apply attrNames"]
  W[build.yml]
  J[justfile]
  T --> E --> W
  E --> J
  classDef deep fill:#0f172a,color:#fff;
  class T deep

Problem: the check inventory has no locality — adding a test needs three edits, and the justfile subset already diverged from CI.

Solution: the checks attrset becomes the interface; workflows and justfile enumerate it via nix eval … --apply builtins.attrNames (enumeration is pure — the IFD only bites on build, which each consumer already does per-attr).

  • leverage: add a check once, both consumers pick it up
  • two real adapters (CI + justfile) justify the seam today
  • kills the silent justfile/CI divergence

C · Quarantine the agent-skills IFD behind a pure-eval seam

Strong ports & adapters

modules/home/claude.nix (agent-skills wiring) · tests/default.nix · auto-update.yml

Before — build inside eval

eval any host config
IFD: build skills bundle mid-eval
checks / --no-build / cross-arch eval

every consumer of eval inherits a build dependency — guard hand-picks attrs, darwin can't eval Linux hosts

After — bundle is an ordinary derivation

eval any host config — pure
skills bundle: plain path composition / build-time only
--no-build works · full flake check returns

the jj skill (claude.nix:336-342) already proves the second adapter: plain path symlinks, platform-agnostic

Problem: the upstream DSL's bundle resolution reads a built derivation during eval; that single leak is behind the May CI wedge, the crippled nightly guard, and the darwin↔linux eval wall.

Solution: compose the bundle from plain paths (the jj-skill adapter, generalized), or pre-render it as a normal build-time derivation the module consumes without reading back at eval.

  • full nix flake check becomes the nightly guard again
  • locality: cross-arch pain stops leaking into every workflow
  • two adapters exist today: IFD path-source vs plain path
⚠ Two prior fixes failed (quarantine PR #75; upstream 6c72d2c) — grill the design before building. Complements ADR-0008 (reproducible dev envs); no ADR conflict.

D · An enable seam for the AI-tool cluster

Worth exploring in-process

modules/home/default.nix · claude.nix · ai-cli.nix · lsp.nix · zed.nix · cursor.nix · droid.nix · amp.nix …

Before

modules/home/default.nix
imports 23 modules, all unconditional

a Linux/Omakub host takes everything or edits module bodies

After

martin.ai.enable (default true)
gates the AI-tool cluster as one unit

terminal/shell/git modules stay unconditional — they're wanted everywhere

Problem: the profile has no partial-composition seam, and the staged Linux target is exactly the second adapter that will need one.

Solution: one cluster-level mkEnableOption for the AI toolchain — not blanket per-module options (Simplicity First: no seam until the second adapter earns it; the Linux host is staged, not live, hence amber).

  • interface stays small: one toggle, not 19
  • unblocks the Omakub profile without module edits

E · Skill curation policy as one table, not four lists

Worth exploring in-process

modules/home/claude.nix:172-241

Before — interface ≈ implementation (shallow)

interface:
4 lists + interaction rules
(duplicate-id throws)
implementation

After — deep

interface: skill → status
compile to enable-lists,
sweeps, transforms;
owns collision rules

Problem: to curate one skill you must know which of four lists to touch (disabled / leanExcluded / removed / transformed) and their non-obvious interactions — the interface is as wide as the implementation.

Solution: one attrset skillPolicy = { grill-me = "disabled"; caveman = "lean"; git-workflow = "removed"; … }; a compile function derives the lists and sweep scripts.

  • interface shrinks; implementation absorbs the rules
  • the per-skill rationale comments survive as values

Top recommendation: Candidate A

It passes the deletion test hardest (deleting the pattern re-scatters ~160 lines of drifting bash), it fixes real correctness bugs — the five DRY_RUN violations — as a side effect of deepening rather than as 5 patches, and the design is already proven in-repo by baseline-activation.nix, so the interface question is "port a known-good shape to the home layer", not "invent one". Candidate C is higher stakes but has two failed attempts behind it — grill it before touching it.
