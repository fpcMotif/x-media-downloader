1 · The durable transfer record carries the Retry Scheduler's duty

Strong local-substitutable (storage.session) fixes live defect

src/entrypoints/background.ts:129,600-604,702-707 · src/core/download/transfer-tracker.ts:19-26 · src/core/download/interrupt-retry.ts

Before — duty dies with the worker

After — record sufficient for every owner's duty

Problem. requestMetaById is in-memory only. Boot reconcile restores ownership of an in-flight transfer but not the duty: a download that interrupts after a service-worker recycle force-fails instead of retrying — silently, and unlike every other recycle trade-off in the file, with no acknowledging comment. The stuck-download watchdog is also never re-armed for re-seeded transfers. ADR-0002 and transfer-tracker's own doc treat mid-download recycle as routine, not an edge case.

Solution. A sibling session-persisted map (id → url/filename/item), written by the same single writer (ADR-0005-compliant), restored inside boot reconcile exactly the way rehydrateInterruptRetries already restores the retry queue; re-arm the watchdog in the re-seed loop. Keep TrackedTransfer narrow — the skeptic's own recommendation — so the Transfer Tracker's interface does not widen.

  • Locality: recycle recovery lives in one boot path
  • Depth: Retry Scheduler interface unchanged; duty becomes durable
  • Tests at the boot-reconcile interface, fake storage adapter
  • Precedent already in-repo: session:interruptRetries persists the same fields

2 · CDN identity joins the registry — narrow slice

Strong in-process fixes live defect

src/core/sync/url-guard.ts:19 · src/core/download/fetched-strategy.ts:8-11 · wxt.config.ts:70-86 · src/core/adapters/registry.ts

Before — one fact, three hand copies, two drifted

wxt.config.ts ✓ grants *.cdninstagram.com (dead entry — never requested)
url-guard ALLOWED_HOSTS ✗ twimg only → UnsafeUrlError on every IG/Threads cloud upload
FETCHED_HOST_PATTERNS ✗ twimg only → Fetched mode never acquires its permission

After — the registry owns the fact

PlatformAdapter.cdnHosts
exact hostnames, no wildcards
url-guard
exact-Set, invariants kept
fetched perms
mapped to patterns
wxt.config
already imports registry

Problem. Cloud Upload and the Fetched Download Strategy are deterministically broken for 2 of 3 platforms whenever enabled — the skeptic traced an Instagram Media Item's URL all the way to guardedFetch with no earlier gate. This is the same disease ADR-0019 cured for page origins: a platform fact hand-copied, then drifted (commit 670d5a6's own message flagged it as an unfixed follow-up).

Solution. One narrowly-typed registry-derived fact — exact CDN hostnames per Source Adapter — consumed by exactly the two drifted lists. The SSRF guard keeps exact-Set membership and all its invariants (derive the set, never switch to wildcard matching); the permission request maps hostnames to match patterns per consumer. Not included: platformFolder and PLATFORM_LABEL — single definition sites, zero drift, folding them in is scope creep (design skeptic).

ADR-0019's "no capability fields" non-decision covers behavioral flags (supportsClear), not identity data — hostMatch is already exactly this kind of field. No conflict; this is the phase-2 the ADR's context anticipated.
  • Leverage: platform #4's CDN reaches both consumers on registration
  • Drift of this class becomes structurally impossible
  • Security posture preserved: exact hosts in, exact hosts out

5 · Overlay: TEMP diagnostics out, preview helpers back to module scope

Worth exploring in-process cheapest first PR

src/entrypoints/overlay.content/index.tsx:1141-1179,1712-1765,746-776

Problem. Two unconditional TEMP diagnostic blocks (not even DEV-gated) ship console.info on every whole-post grab and every hovered element. And previewSrcFromMedia/previewKeyFromMedia — module-scope pure functions before commit 04210fc — were moved inside main() to close over the adapter: a straight testability regression for unchanged behaviour.

6 · Wire-contract hygiene: dead tags, schema-less tags, twin ports

Worth exploring in-process

src/core/schema/index.ts:201-245,479-509 · src/entrypoints/overlay.content/handlers.ts:519-529 · src/background/sync-outbox.ts:33 · src/background/capture-outbox.ts:37

Problem. Three Message-union tags are dead (DetectRequest, MediaDetected, MetricsUpdate — zero senders, verified). Four tab-directed tags (ClearVisible/ClearWholeList/DrainPage/SweepPage) have no schema definition at all and two more sit outside the union — the overlay dispatches them untyped, no decode gate. Two byte-identical ConvexPort declarations force two families of hand-built fakes (14 across two test files).

Solution. Delete the three dead tags; give the six tab-directed tags real schemas in a separate TabMessage union — the skeptics established they ride a different transport (tabs.sendMessage), so folding them into Message would conflate two wire contracts. Unify the twin ConvexPort into one import with one fake builder.

This is the surviving 20% of the "Extension Bus" idea. The bus itself is in the graveyard below.
  • The wire contract matches reality again
  • Typed decode gate for tab-directed messages
  • Locality: one ConvexPort, one fake

Killed this round — do not re-propose

  • Extension Bus (one deep send()): the error-posture variance across call sites is essential, not accidental — safeSend's discriminated union already is the deep module; popup/options genuinely don't need the triage; exhaustiveness checking is blocked on the two-transport reality.
  • Capability gates from optional-member presence: postGrabEligible is an overloaded product flag that also gates the inline-data harvest; the recovery dispatch is hardcoded to X inside detection-store.ts:279 (the adapter's findMediaNeedingRecovery field is vestigial) — a presence check would lie about how dispatch works.
  • makeOutboxDrainer (any scope): the three drain loops diverge on every structural axis — batch-of-64 / all-due / exactly-one; stop-on-failure / swallow / continue-past-failure; no-lease / no-op-claim / CAS-with-fencing-token; alarms only in cloud-upload. Textbook forced generalization.
  • 3-way Terminal Outcome unification: contradicts ADR-0014's "aria2 emits no backlink" invariant three times over. Narrow fix shipped as card 3 instead.
  • Platform-facts full scope (folder names, display labels): single definition sites, zero drift — folding them into the security-relevant CDN field is blast-radius growth for nothing.
  • Round-4 hygiene batch: already landed (db90a35) — card.tsx deleted, runUpload → dispatchToProvider done.

Top recommendation

Candidate 1 — the durable transfer record carries the Retry Scheduler's duty. The only candidate both skeptics fully confirmed, it fixes an undocumented silent-degradation defect in the flow the whole extension exists for, and the repo already contains its own precedent (session:interruptRetries persists exactly these fields). Tests land at the boot-reconcile interface and survive internal refactors.

Independent of any exploration choice: card 2's two drifted CDN lists and card 3's sidecar guard are live-defect fixes small enough to ship immediately; card 5 stops shipping debug logging to users today.
