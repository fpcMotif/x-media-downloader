xtimelinefilter · branch claude/convex-mirror · 2026-07-02 · working tree reviewed as-is (~30 uncommitted in-flight files)

Method: six parallel survey agents (five subsystem reviewers + one facts cataloger) fanned out over content layer, x-client, core state, UI surfaces, and test architecture; every finding below was then verified against the code — the load-bearing ones by direct re-reads of the implicated files, the rest by targeted greps. Verdict

This codebase is in the top tier of what the review vocabulary calls good architecture: real deep modules (filter-applier, synced-store, caret-actions' run()), real two-adapter seams with contract tests that prove their own teeth, one projection home per derived fact, and ADRs + a domain glossary that the code actually follows. The 20 points below are dominated by localized frictions — but three are genuine behavioral defects (a strict write that reads back as success after failing, a filter undo that visibly does nothing, and a test-double sprawl that taxes every new storage test).

// src/core/synced-store.ts
export function syncedStore<T extends object>(
  key: string,
  defaults: T,
  area: StorageLike,
  areaName: "sync" | "local" = "sync",   // ← the parameter and the listener stop disagreeing (pt 10)
): SyncedStore<T> {
  // …
  async write(next: T) {
    const prev = cache;
    const echo = JSON.stringify(next);
    cache = next;
    pendingEchoes.add(echo);
    try {
      await area.set({ [key]: next });
    } catch (err) {
      // A rejected write must not read back as success: restore the cache
      // (unless a newer write already superseded it) and retire the echo
      // that will now never arrive.
      if (cache === next) cache = prev;
      pendingEchoes.delete(echo);
      throw err;
    }
  },

  onExternalChange(cb) {
    watchStorageKey(areaName, key, (raw) => { /* unchanged */ });
  },

// tests/support/storage.ts
import type { StorageLike } from "@/core/settings";

/** Seedable in-memory StorageLike mirroring chrome.storage area semantics. */
export function fakeStorage(
  seed: Record<string, unknown> = {},
): StorageLike & { readonly data: Record<string, unknown> } {
  let data: Record<string, unknown> = { ...seed };
  return {
    async get(keys) {
      if (keys == null) return { ...data };
      const list = typeof keys === "string" ? [keys] : keys;
      return Object.fromEntries(list.filter((k) => k in data).map((k) => [k, data[k]]));
    },
    async set(items) {
      data = { ...data, ...items };
    },
    async remove(keys) {
      for (const k of typeof keys === "string" ? [keys] : keys) delete data[k];
    },
    get data() {
      return data;
    },
  };
}

// src/core/storage-blob.ts — three adapters exist on day one (coach, list-usage, list-cache)
import type { StorageLike } from "@/core/settings";

/** Read one JSON blob stored under `key`; missing key yields `fallback`. */
export async function readBlob<T>(area: StorageLike, key: string, fallback: T): Promise<T> {
  return ((await area.get(key))[key] as T | undefined) ?? fallback;
}

/** Serialized read-merge-write: concurrent patches queue instead of losing updates. */
export function blobWriter<T extends object>(area: StorageLike, key: string, fallback: T) {
  let chain: Promise<unknown> = Promise.resolve();
  return function patch(p: Partial<T>): Promise<T> {
    const step = chain.then(async () => {
      const next = { ...(await readBlob(area, key, fallback)), ...p };
      await area.set({ [key]: next });
      return next;
    });
    chain = step.catch(() => {}); // a failed patch never wedges the queue
    return step;
  };
}

Kills the coach lost-update race (pt 17) as a side effect of deduplicating the idiom (pt 9) — the race fix lands where the logic is called, preserving locality. The deletion test passes: removing this module would scatter serialization back into three files.

filter-applier owns classify/collapse/restore/reapply/isStubbed end-to-end: no caller touches the FILTERED/STUB/TRACELESS attributes, and recycle-safety, fail-open guards, compact-mode CSS, and hydration re-classify all hide behind five call sites' worth of tiny surface. When traceless hiding was added, main.tsx needed only isStubbed() — nothing downstream changed.

Lesson: a module has earned "deep" when a new internal capability lands and no caller has to learn anything. Watch for that moment — it is the strongest available evidence the seam is drawn in the right place.
src/content/filter-applier.ts

2 · Contract tests that prove their own teeth — and name their divergences

The MembershipStore contract runs both adapters through one suite, then feeds itself deliberately broken implementations to prove it would fail on a regression. The XListApi contract splits universal behavior, HTTP-only parity, and one named intentional divergence (REST vs GraphQL rule order on a code-88+104 payload) into three blocks — so drift toward false symmetry fails as loudly as a contract break.

Lesson: a shared contract is only trustworthy if you've watched it fail; write the negative case beside it. And give deliberate asymmetries their own named test — assert the difference, don't bury it in one adapter's file.
tests/core/membership-store/contract.test.ts tests/core/x-client/contract.test.ts

3 · Derived facts have exactly one home — divergence became impossible, not just tested-against

filter-projection is the only place any surface computes the active-criteria count or palette catalog (born from a real pill-vs-popup disagreement bug), and CriteriaMatrix is a true second-adapter extraction: three props, each independently load-bearing (conduct routes through the fail-open wall in-page; Options runs direct), replacing two divergent chip implementations.

Lesson: when two surfaces can independently derive the same fact, they eventually will — differently. The fix is not more per-surface tests; it is deleting the second derivation. Extraction is justified by the second real caller, not by imagined reuse.
src/core/filter-projection.ts src/ui/criteria-matrix.tsx

4 · The verified-action pattern is factored exactly once — and its tests only trust observable effects

One run() driver (open menu → wait for row → activate with re-find retry → wait for menu close → confirm) parameterized by only a row predicate and a confirm mode. Its test fixture makes the fake menu actually vanish on click — testing "X accepted the action," not "a click was dispatched." The hydration observer's comment cites the live-verified X quirk it exists for, with the doc that proves it.

Lesson: for automation against a platform you don't control, define success as an observable effect and make fixtures reproduce that effect. Parameterize shared act→verify→retry machinery by what actually varies (a predicate + an enum) — and write comments as citations of observed failure modes, not descriptions of code.
src/core/x-client/caret-actions.ts tests/core/x-client/caret-actions.test.ts src/content/filter-applier.ts

5 · Regression tests pin invariants the test environment structurally cannot reproduce — and say so

store-stability.test.tsx doesn't try to reproduce the infinite render loop happy-dom's scheduler dampens; it asserts the invariant whose violation causes it (createSettings/createFilterStore called exactly once per prop-less mount) and documents why a behavioral repro is impossible. The docstring names the live failure ("flips then reverts") and the environment gap.

Lesson: when the environment can't reproduce the symptom, don't fake it — assert the invariant and record why in the test itself. This is the template for every environment-fidelity gap (shadow-DOM retargeting is the next candidate).
