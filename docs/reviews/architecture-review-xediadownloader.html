Candidate 1 — Platform identity derives from the registry

Strong dependency: in-process skeptics 3–0 TOP RECOMMENDATION
src/core/adapters/registry.ts

Problem: ALL_ADAPTERS is a real deep seam for content-script matches, but five consumers hand-maintain their own copy of platform identity, and copies drift silently — one shipped incident (sender-guard, fixed 670d5a6 after a 3-commit debugging spiral), one LIVE bug (tab-broadcaster still queries only X tabs, so a failed download on Instagram/Threads keeps a false "saved" badge forever), one accidental-safety foot-gun (clear-family handlers have zero platform gate), a popup that tells users "Open X or Twitter" while the overlay underneath is live, and a manifest synced by comment convention.

Solution: registry.ts grows derived helpers (originsForAllAdapters(), allPlatformHostMatch()); sender-guard, tab-broadcaster's generic broadcast, and the popup consume them; clear-family handlers get an explicit platform gate in the message contract; a test pins wxt.config.ts's manifest arrays ⊇ ALL_ADAPTERS hostMatch. Deliberate non-goal: no capability fields on the adapter record — clear support has one adapter today; one adapter = hypothetical seam.

Candidate 2 — Deepen the message-reply contract

Strong dependency: in-process skeptics 3–0
src/core/messaging.ts:29-46
src/core/sender-guard.ts:22
src/entrypoints/overlay.content/index.tsx:293,518,785
src/core/schema/index.ts

Problem: when the background listener declines a message, Chrome resolves the sender with reply:undefined and safeSend reports {status:'ok'} — a guard-drop is indistinguishable from a legitimate empty reply; this exact conflation shipped two silent-failure incidents (012254b, 670d5a6), each diagnosable only in a live browser; meanwhile CONTENT_SCRIPT_TAGS is an untyped ReadonlySet<string> and three overlay call sites hand-cast replies, duplicating QueueUpdate's fields by hand ("failures" nearly drifted).

Solution: (1) type CONTENT_SCRIPT_TAGS against Message['_tag']; (2) make guard-drops loud — treat reply===undefined as a distinguishable unclaimed outcome and generalize the existing Capture-tags console.warn pattern, spiking the MV3 sendResponse-before-return-false question before any SendOutcome variant; (3) decode the three call sites through the schema types that already exist. Explicitly NOT a messageClient module (that was refuted in an earlier round) — this tightens the existing seam.

BEFORE
AFTER
Wins
  • silent drop → loud, testable outcome
  • interface: reply shapes pinned to schema
  • kills a two-incident bug class
  • no new module — depth at the existing seam
Sequencing: land (1)+(3) first — pure type-tightening, zero behavior change; (2) is the only piece needing new tests.
