Glossary — Monads & Category Theory

Compressed reference for the x-media-downloader Effect refactor. Each term maps to the concept and to the code you actually wrote.

The category

Category
Objects + morphisms (arrows) + a composition ∘ + an identity per object, obeying associativity and identity laws.
Object / Morphism
In programming: objects = types; morphisms = functions A → B.
Composition ∘
(g ∘ f)(a) = g(f(a)). The whole game is: which arrows compose, and how?
Identity
id: A → A, a ↦ a. The do-nothing arrow that composition must respect.
The laws
h ∘ (g ∘ f) = (h ∘ g) ∘ f  (associativity)
f ∘ id = f = id ∘ f  (identity)

Functor

Functor
A structure-preserving map between categories: sends objects→objects and arrows→arrows, preserving ∘ and id.
Endofunctor
A functor from a category to itself. Option is an endofunctor on "types & functions".
Effect/TS: on types T ↦ Option<T>; on functions Option.map(f).
Functor laws
map(id) = id
map(g ∘ f) = map(g) ∘ map(f)

Monad

Monad
An endofunctor T plus two natural transformations: unit η and multiplication μ — obeying the monad laws. Equivalently: a way to compose functions whose results are "embellished" by T.
unit / η
Wrap a plain value: η : A → T A.
Effect/TS: Option.some (a.k.a. of); for errors, Either.right.
multiplication / μ (join)
Flatten one layer: μ : T(T A) → T A.
Effect/TS: Option.flatten.
bind / flatMap (>>=)
The everyday form: T A → (A → T B) → T B. Equivalent to η + μ.
Effect/TS: Option.flatMap.
Monad laws
flatMap(some(a), f) = f(a)  (left identity)
flatMap(m, some) = m  (right identity)
flatMap(flatMap(m,f),g) = flatMap(m, x => flatMap(f(x),g))  (associativity)

Kleisli

Kleisli category Kl(T)
Same objects (types); a morphism A → B is a function A → T B. Built from any monad T.
nLab: Kl(T)(X,Y) := C(X, T Y); composition μ ∘ T(g) ∘ f.
Kleisli arrow
One such function. Your convexOriginPattern: string → Option<string> is a Kleisli arrow in Kl(Option).
Fish operator >=>
Kleisli composition: (f >=> g)(a) = flatMap(f(a), g). Identity is η (some).
Key fact
The monad laws are exactly the category laws (assoc + identity) for Kl(T). That is the whole point: a monad is what makes embellished arrows compose.

The data

Sum type / coproduct T + 1
Option<T> = Some T | None is the type T plus one extra "nothing" value.
Option / Maybe
The monad for partiality (absence). Kl(Option) = the category of partial functions.
Either / Result
The monad for failure with a reason: Either<E, A>. Maybe<T> ≅ Either<unit, T>.
Effect/TS: Either, and your Data.TaggedError in Effect's typed error channel.
Railway-oriented programming
Wlaschin's metaphor for Either: a happy "success track" and a "failure track"; None/Left bypasses the rest. fsharpforfunandprofit.com/rop.

Errors (Either & Effect)

Right-biased
Either’s map/flatMap act on the Right (success); a Left (error) passes through untouched — the “failure track” short-circuits.
Bifunctor / mapLeft / bimap
Either is a functor on both type params: map the success, mapLeft the error, bimap both. Each side obeys the functor laws.
Error channel · Effect<A, E, R>
Effect’s type: A success, E error (the Either Left, typed), R requirements. Multiple errors accumulate as a union in E automatically.
Your DownloadStrategy.save: SaveRequest → Effect<DownloadHandle, DownloadError> is a Kleisli arrow over the Effect monad.
Failure vs defect · fail vs die
Failure (Effect.fail): expected, domain, recoverable, typed in E (like a checked exception). Defect (Effect.die): unexpected bug/invariant violation, untyped (E = never), terminates — like an unchecked exception. This line is where “don’t reinvent exceptions” lives.
Data.TaggedError
Builds an error class with a _tag discriminant + typed fields; yieldable (usable directly in Effect generators).
Your OAuthError, Aria2RpcError, OffscreenSaveError, the Convex errors.
catchTag / catchTags
Handle a specific tagged error by its _tag; the compiler narrows the remaining error union. Exhaustive handling = clearing E to never.
Cause
Effect’s lossless record of why an effect failed (typed failures, defects, interruptions, traces) — no information is thrown away, unlike a bare throw.

Property-based testing

Property-based test
Assert a property that must hold for all inputs, then let the framework generate hundreds of random cases to try to falsify it — instead of one hand-picked example. Origin: QuickCheck (Claessen & Hughes, 2000).
Arbitrary / generator
A recipe for random inputs. fast-check: fc.string(), fc.nat(), fc.webUrl(), fc.array(a), fc.record({…}), a.map(f), fc.oneof(a,b).
Shrinking
On failure, the framework searches for the smallest input that still fails — handing you a minimal counterexample, not a 500-element noise case.
Law as a test
A functor/monad law written as a property: fc.assert(fc.property(gen, (m) => eqOption(map(m, id), m))). A law you can run is knowledge; one you only believe is a hope.

The Effect monad (R & Cause)

Effect<A, E, R>
One lazy value fusing three monads: A success (Task/async), E failure (Either), R requirements (Reader). Roughly R → Promise<Either<E, A>>, inert until run.
R / Requirements (Reader channel)
The services an effect needs to run. R = never ⇒ self-contained. Read R1 | R2 as “needs R1 and R2.”
Your Effect.Effect<A, E, SettingsService> — needs a SettingsService.
Context
A type-safe map Tag → Service; the DI container the R channel reads from.
Tag / Service
A unique identifier + its implementation. (Effect 4: Context.Service.)
Your class SettingsService extends Context.Service<…>.
Layer
A composable, effectful recipe for building services (handles their own deps + resources).
Your SettingsServiceLive = Layer.succeed(SettingsService, …).
provide
Discharge a requirement — supplies a service, shrinking R toward never, after which the effect can run.
Your Effect.provide(eff, SettingsServiceLive) then Effect.runPromise.
Exit
The result of running an effect: Success(A) | Failure(Cause<E>).
Your tests’ Effect.runPromiseExit + Exit.isFailure.
Cause (semiring)
The lossless record of why an effect failed. Leaves: Fail (your tagged failures), Die (defects), Interrupt; combined by Sequential & Parallel — so concurrent failures and finalizer errors are all kept (a semiring over E).
Layer<ROut, E, RIn>
A recipe that produces services ROut, requires RIn, may fail with E. Construction is itself effectful (it can acquire resources).
Layer.provide / Layer.merge
provide feeds one layer’s outputs into another’s requirements (composition ∘ of recipes). merge / mergeAll place layers side-by-side (a product of outputs).
Layer memoization
Layers are shared by reference: the same layer instance in the graph is built once — so a stateful service has one shared Ref. Store parameterized layers in a const and reuse it.
Ref<A>
A mutable reference holding an immutable value; atomic get/set/update — the effectful “State” cell. Create with Ref.make inside Layer.effect, keep it private, expose methods.
Your folderCache: Map → a FolderCache service backed by a Ref.
Manual DI ≅ Reader-by-hand
Passing a dependency as a parameter (your cfg.fetchImpl, DriveDeps) is the Reader monad threaded by hand — the result type doesn’t record the need. The R channel + a Layer let the compiler track and swap it. provide = applying the environment.
